## 1. The issue

**Intended method (restated 2026-09-30):**
- Weighted gradients go **only** to the climate feature encoder and the
  climate-delay parameters.
- **All** prediction heads, the climate correction head included, get
  ordinary unweighted gradients.

**Two symptoms:**
- The research brief lists the climate head in the weighted group
  (`docs/Research_Paper_New.md:182`: "lag encoder, climate GRU, climate
  head").
- The results report that h=4-only training left the h=1–3 climate heads
  at zero (`docs/climate_horizon_results.md:159`,
  `docs/climate_horizon_implementation.md:1170`).

## 2. What the code actually did

**Grouping.** `ClimateHorizonNB.climate_parameters()`
([src/models/climate_horizon.py:157-161](../src/models/climate_horizon.py#L157-L161))
returns

```python
[*self.encoder.parameters(), *self.climate_gru.parameters(), *self.climate_delta.parameters()]
```

`self.climate_delta` is the climate correction head, `nn.Linear(16, 4)`
([:146](../src/models/climate_horizon.py#L146)).
`other_parameters()` is everything else
([:163-167](../src/models/climate_horizon.py#L163-L167)).

**Gradients**
([src/training/climate_weighting.py:84-96](../src/training/climate_weighting.py#L84-L96)):
- `torch.autograd.grad(loss_climate, climate_parameters)` for the climate
  group, where L_climate = Σ a_h w_h L_h / Σ a_h w_h;
- `torch.autograd.grad(loss_equal, other_parameters)` for the rest.

Each gradient is assigned once
([:122](../src/training/climate_weighting.py#L122)). One global-norm clip
over all parameters follows ([:123](../src/training/climate_weighting.py#L123)),
then one Adam step ([:129](../src/training/climate_weighting.py#L129)).
The backward-only `_GradScale` router
([src/models/climate_horizon.py:195](../src/models/climate_horizon.py#L195))
is fixed at weight 1 and has no effect.

**Optimiser**
([src/training/climate_horizon.py:76-83](../src/training/climate_horizon.py#L76-L83)):
- the lag encoder gets lr 2e-2 with no weight decay;
- every other parameter gets lr 3e-3 with weight decay 1e-4.

### Numerical confirmation
- **F arm (weights 0,0,0,1).** In all 27 saved checkpoints the climate-head
  rows for h=1–3 are exactly zero (max |weight| = 0, |bias| = 0), and the
  h=4 row is non-zero (max |weight| 0.38). This is
  `grouping_audit/h4_only_head_rows.csv`. The rows start at zero, get zero
  gradient from L_climate, and Adam's weight decay of a zero parameter is
  zero, so they never move. The model was therefore climate-free at
  h=1–3, not "climate learned from h=4 only".
- **Constant non-zero weights.** Head row h receives gradient from horizon
  h alone, so a constant weight w_h scales that row's gradient by a
  constant. Adam normalises per element. One Adam step with per-row scales
  0.41–1.65 changed the update by at most 1.2 × 10⁻⁵ relative
  (`grouping_audit/head_row_scaling.json`).
  - For constant non-zero weights (arms C, D, E, G), misplacing the head
    should therefore have had only a small effect, through eps, weight
    decay and global clipping.
  - This is an expectation, not a measurement: the affected arms still
    have to be retrained to confirm it.
  - For zero weights (F) and time-varying weights (H, GradNorm), the
    effect is real.

## 3. Verdict: both an implementation error and a documentation error

- **Implementation error (against the stated specification).** The step-4
  specification put "output heads" in group 2 ("all other parameters,
  including case GRU, gate and output heads"). The code put the climate
  output head in group 1
  ([src/models/climate_horizon.py:160-161](../src/models/climate_horizon.py#L160-L161)).
- **Documentation error.** The docs describe the implemented grouping as
  if it were the method, without flagging that it departs from the
  specification:
  - implementation doc §9 (lines 606–607) and §13 (lines 924–925);
  - brief §5.2 (line 182).

  The F-arm reading ("climate learned only from h=4") also misdescribes
  what F did: F removed climate from h=1–3 entirely.
- **The frozen manifest froze the error.** The manifest's "loss" text says
  only "climate group". But its SHA-256 of `src/models/climate_horizon.py`
  fixes the as-run grouping. So every retrospective and 2026 result is
  faithful to the manifest, and the manifest itself does not match the
  intended method.

## 7. Correction implemented: routing v2 (2026-09-30, after the audit)

**Code change (smallest possible).**
- `ClimateHorizonNB.climate_parameters()` now returns only `encoder.*` and
  `climate_gru.*` ([src/models/climate_horizon.py](../src/models/climate_horizon.py)).
- `climate_delta` moved to `other_parameters()`, so it now receives the
  unweighted L_equal like every other prediction head.
- A constant `ROUTING_VERSION = "v2-heads-unweighted"` records the fix;
  the as-run version was v1.
- **No parameter is shared between the groups.** The encoder still gets
  its weighted gradient *through* the head's forward computation.
- **Learning rates and weight decay are unchanged for every parameter.**
  Optimiser groups are built from the encoder only, so `climate_delta`
  keeps lr 3e-3 and weight decay 1e-4, exactly as in the audit table
  (tested).
- The NB loss reduction, architecture, optimiser, clipping and the single
  update step are unchanged.

**Second, related guard** (`src/training/climate_weighting.py`). A batch
with no observed target now produces no gradients and skips the optimiser
step. Before, Adam's weight decay could move parameters on all-zero
gradients. The 5-epoch fold-9 smoke run had 0 such batches. Because every
training origin has at least one observed cell, this is not expected to
affect equal-weight runs, but the reruns will log it.

**Tests** (`tests/test_climate_routing_correction.py`; float64; warm-up
before checks, because zero-initialised heads give zero encoder gradients
at step 0):
1. The groups are exact and cover every parameter once, with unchanged
   lr and weight decay.
2. Uniform weights reproduce the baseline raw gradients and the Adam
   update from identical model and optimiser states.
3. Non-uniform weights change only the climate group's **raw** gradients.
   Both heads' gradients are bit-identical. Final updates are not compared,
   because global clipping may legitimately differ.
4. Routed encoder gradients equal Σ a_h w_h ∇L_h / Σ a_h w_h, computed
   independently per horizon.
5. With h=4-only weights, all four rows of the climate, case and
   dispersion heads receive gradients and learn.
6. With h=4-only weights, the routed encoder gradient equals ∇L_4 exactly.
7. Missing targets (NaN), empty batches (no update at all) and zero active
   climate weight (encoder frozen, heads still learn) are handled.

The legacy backward-only router test was narrowed. That router is unused
(fixed at 1). It scales at the head's output, so it no longer leaves the
head untouched.

### Estimands
- **Seed-mean MAE.** Scripts 47 and 49 average the per-seed MAEs of a fold
  (`ev.score` groups by method, seed, fold and horizon; `metrics_by_fold`
  then averages over seeds). Headline values average folds with equal
  weight.
- **Ensemble MAE.** Script 49 (`horizon_table`, estimand "ensemble")
  averages each cell's seed predictions first, then scores them.
- **RMSE and peak MAE** follow the same split:
  - seed-mean: the mean over seeds of per-seed RMSE or peak MAE;
  - ensemble: RMSE or peak MAE of the seed-averaged forecast.
- **Required numerical check** (target 10, seed predictions 0 and 20):
  seed-mean MAE 10, ensemble MAE 0; RMSE 10 and 0; peak MAE 10 and 0.
  All pass, together with a check that `ev.score` averages per-seed errors.
- **On real data** (B, fold 1, h=1): the recomputed seed-mean MAE is
  40.75231, identical to script 47 (difference < 1e-4). The ensemble MAE
  is 40.198, and they are reported separately.

### Pairing and coverage
- Pairs are matched on fold, district, target period and horizon. The
  forecast origin equals target − h, so it is matched too.
- Only observed cells are scored. The intersection covers all methods:
  11,725 cells per horizon retrospectively and 474 in 2026, with coverage
  100% (the stored references carry one extra, unobserved, 2026 cell).
- **Seeds.** Each arm's seeds are averaged per cell before differencing.
  For the seed-mean estimand, that equals the mean of seed-by-seed paired
  differences when both arms share seeds (B and D: seeds 0–4). Seeds are
  never treated as independent observations.

### Bootstrap
- **Target.** It estimates the reported quantity: the mean over folds of
  the per-fold seed-mean difference.
  - Bootstrap and reported deltas agree to 1.3e-15 at every horizon
    (`bootstrap_point_check.csv`).
  - A test confirms equal fold weighting under unequal cell counts.
- **Resampling unit.** Contiguous blocks of target weeks, which are
  contiguous forecast origins for a fixed h, drawn within each fold.
  Every district of a week moves with its block (tested). Blocks do not
  overlap and the last block may be short.
- **`p_boot`** is a percentile sign statistic
  (2·min(P(Δ*≤0), P(Δ*≥0))), not a p-value under a null hypothesis. It
  was not used in any decision. The declared decisions use Holm-adjusted
  t-tests and the CI.
- **What it does not address.** It does not resolve dependence from
  overlapping training histories across folds.

### Block-length sensitivity (post-hoc; retrospective folds; `block_sensitivity.csv`)

- Longer blocks give **narrower** intervals. With about 52 weeks per fold,

  intervals are therefore **not** more conservative. The declared 4-week
  result stands.

  4-week blocks).

  blocks, and includes zero with 13-week blocks. At h=1–3 it includes
  zero at every length.
- **2026** (19 weeks) has only 5 four-week blocks. 8- and 13-week blocks
  were not computed for it, because they would leave 2–3 blocks.

## 10. Exploratory 2×2 factorial: lag alignment × climate weighting (2026-09-30)

**Status: exploratory and post-hoc.** This decomposition was designed
after all results for A–D had been seen. It is **not** the primary
hypothesis. The primary hypothesis remains D vs B with 5 seeds (§9: null).

**Script:** `scripts/evaluation/56.climate_horizon_factorial.py`.
**Outputs:** `correction_2026-09-30/factorial/`.

### Inputs
- **Arms.** A and B use the v1 files, which are verified equivalent: equal
  weights, and B is bit-identical under v2. C and D use the corrected v2
  reruns.
- **Seeds.** 0, 1 and 2 for all four arms, the seed IDs they share. B and
  D's seeds 3–4 are excluded here, so the 5-seed primary comparison is not
  mixed in.
- **Cells.** The intersection of all four arms' observed test cells:
  11,725 per horizon. Every arm has the complete seed set.
- **Folds.**
  - **All 9** retrospective folds (2017–2025).
  - The **historical headline 7**, which excludes COVID folds 4 and 5
    (2020–21). They were excluded under the original protocol because
    COVID-period reporting disruption makes them non-comparable. They are
    included in "all 9".
- **Statistic.** The mean over folds of the per-fold mean per-cell
  contrast of seed-mean absolute errors. Negative means the first term is
  better.
- **Uncertainty.** 4-week block bootstrap of contiguous origins, all
  districts together, within folds (years held fixed).
- **Across-year evidence.** Fold-level paired t-test and Wilcoxon.
- **Multiplicity.** Holm over all 20 contrast × horizon tests within each
  fold set.

### How to read it
- **Block CIs and fold-level tests disagree, and the difference matters.**
  - Many block-bootstrap CIs exclude zero. **None** of the 20 fold-level
    tests survives Holm (smallest adjusted p 0.65).
  - The bootstrap holds the nine years fixed and measures within-year
    uncertainty. The fold-level tests ask whether the effect recurs across
    years.
  - The effects are concentrated in a few folds. At h=4:
    - B−A is −2.63 in 2017 and −1.18 in 2019, and between −0.24 and +0.21
      in every other year;
    - C−A is −3.29 in 2017 and −1.32 in 2019.
  - They are therefore **not established as general effects**. Most of
    each estimate comes from the 2017 epidemic and 2019.
- **Descriptively, weighting only helps with origin-relative lags.**
  - With origin-relative lags, measured weights improve on equal weights
    (C−A, 6–7 of 9 folds).
  - With target-relative lags they do nothing (D−B about 0).
  - Target-relative lags help with equal weights (B−A < 0) but hurt with
    measured weights (D−C > 0).
  - The interaction is positive at every horizon.
- **Seeds matter.** With seeds 0–2, D−B is −0.02 to −0.06. With the
  declared 5 seeds (§9) it is +0.06 to +0.08. The difference between the
  two seed subsets (about 0.1 MAE) is larger than the D−B effect itself.

- **Indexing.** Verified by exact tests (`tests/test_horizon_lag_encoder.py`):

    h = 1, 2, 4;
  - origin mode reads x[t−k] at every horizon;
  - data after the origin cannot change a forecast.
- **Observed history.** Identical in both modes: 26 weeks (k = 0–25),

### What is measured, and what is only a hypothesis
- **Measured.**
  - Measured weights change each climate-encoder step only modestly: about
    13% of the update vector, cosine 0.99.
  - Clipping never fired, so the other parameters' updates are identical.
  - The per-horizon gradients are partly aligned (cosine 0.48–0.68 with
    h=4). Weights of 0.4–1.9 therefore rotate the combined gradient by
    only about 10° (cosine 0.986).
  - Across a full training run, B and D end up closer to each other than
    two seeds of B are, on predictions, gates, corrections and kernels.
- **Not supported.** Clipping explains nothing here, because it was never
  active.
- **Hypotheses (not tested).**
  - The small per-step rotation, repeated over training, is too weak
    relative to seed-driven variation to move accuracy measurably.
  - Adam's per-element normalisation makes the update norm less sensitive
    than the raw gradient norm (+2.5% vs +14%). But the update direction
    still changed, so Adam alone does not explain the null result.
  - Only weights far from uniform (e.g. F's 0/0/0/1) change the encoder
    materially. That is consistent with corrected F's larger effect, but
    it was not tested causally.
- **Limits.** 3 folds, 2 seeds, 5 batches, final states only (not
  earlier training states); post-hoc.
